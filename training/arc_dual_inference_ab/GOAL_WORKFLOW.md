# Goal workflow for Arc inference experiments

1. **Goal:** Arc remains the director and returns one useful, grounded answer while balancing precision and creative alternatives.
2. **Learning-loop gate:** follow the current LOCI `mac-install/scripts/learning_loop.py` at commit `d344898f96db96f8ea13e33a5e8d098139fa4aac`: ethics classification first; check the solution counter for a known task; forecast likely failure vectors before acting; retrieve up to five LOCI seed entities for novel tasks; record an outcome only after completion and only when not in dry-run. This is an interpretation of the source code, not a claim that the script was run. Review local `ethics_filter.py`, `solution_counter.py`, and `forecast.py` behavior before integrating it; this pack does not import or execute them.
3. **Outcome measures:** factual support, coverage of constraints, useful connections, relevance, tone/acknowledgment, uncertainty calibration, consistency, latency, and transferred bytes. Score each output against a written rubric; keep subjective human ratings separate from automated measures.
4. **Baseline:** freeze prompt set, context, model/checkpoint hash, quantization, tokenizer, sampling settings, seed list, endpoint, warm-up policy, hardware state, and timeout. Record unknowns rather than infer them.
5. **A/B:** A routes by category and runs speculative draft/verify with TRS disabled or enabled as a separately labeled factor. B runs evidence/constraints and alternatives/impact streams concurrently, then Arc arbitrates and synthesizes. Keep output budget and context equal.
6. **Evidence:** store run ID, UTC timestamp, input hash, code revision, configuration hash, latency stages, resource telemetry, outputs under the chosen retention policy, evaluator scores, and disagreements. Never store secrets. For privacy-sensitive deployments, use hashes and local-only storage.
7. **Decision:** report paired differences and uncertainty; identify regressions by category; do not declare a winner on aggregate score alone. A human reviews examples with disagreement or safety impact.
8. **Stop condition:** stop on missing provenance, model/config drift, endpoint failure, unsafe output, unexpected remote egress, or resource contention. Preserve the run record and revert experimental routing without changing weights.
9. **Learning loop:** only after review, create a proposed change with expected effect and rollback. Validate against a held-out set before any model adaptation. In this pack, “learning” means comparing and recording protocol behavior; no autonomous weight updates occur.
